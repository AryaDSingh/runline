# M2b: Feel (Options, Camera Effects, Look Limits, Arms) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the runner feel like a body is carrying the camera, and let the player set their own controls. That covers four pieces:
- an options menu: sensitivity, invert Y, field of view, camera motion;
- faith-runner's camera effects (`camera.rs`: bob, sway, tilt, landing kicks, shake, FOV);
- faith-runner's look rules (`look.rs`: per-move look limits and the swan neck);
- the template's first-person arms.

**Architecture:** `look.rs` and `camera.rs` are ported into RunlineCore (plain C++, as in M1) and checked against faith-runner:
- **Camera effects and swan neck:** trace v5 adds an `fx` record per frame. The recorder runs a `CameraFx` and a `SwanNeck` over the traced controller, and the replay runs the C++ ports beside the controller and compares them bit for bit.
- **Look limiter:** it mutates the controller, which the recorder can't clone, so it is checked with a golden table and faith-runner's own unit tests.

In Unreal, the movement component runs the limiter, `CameraFx` and `SwanNeck` once per step, right after the core step, exactly where faith-runner's app runs them. The render view then interpolates the effect offsets between steps, just as it does the eye. Settings live in a config-backed `URunlineSettings`. The options and pause menu is Slate, built in code, with no assets.

**Tech Stack:** C++20 RunlineCore (doctest), Rust (trace patch, tools/golden), UE 5.8 (Slate, Enhanced Input, automation tests), the template's Manny mesh and anim BPs.

**Spec:** `docs/superpowers/specs/2026-10-09-faith-movement-port-design.md` (M2: "CameraFx, template first-person arms"; §3 fixed step and interpolation)

**User feedback this plan answers (M2a playtest, 2026-10-10):** everything played right (wallrun, slide, the checklist) except:
1. the mouse is too slow;
2. crouching feels floaty and delayed;
3. there should be an options menu with "the basic stuff games have for controls".

The user expects animation and bob to fix most of the floatiness. Item 1 is a setting, not a bug: Enhanced Input already passes raw counts, and 0.0022 rad per count is faith-runner's own default. Item 2 gets re-checked after Tasks 5-6.

## Global Constraints

- RunlineCore: C++20, no Unreal headers, metres, Y up, float, `/fp:strict`. Port faithfully: the same names in CamelCase, the same constants, and the Rust doc comments carried over. `FMin`/`FMax`/`FClamp`, never `std::min`/`max` on floats. `f`-suffixed literals. ASCII sources. (CLAUDE.md)
- Every ported behaviour has a test; golden or trace tests guard parity with the Rust original. (CLAUDE.md)
- Unit and axis conversion happens only in `RunlineUnits.h`. (spec §3, M2a)
- The core steps at a fixed 1/60 s. Only the camera and arms are interpolated between steps, and mouse look is never delayed. (spec §3)
- Credit faith-runner, and never commit Mirror's Edge files. (CLAUDE.md)
- Trace tooling: the patch lives in `tools/trace/faith-runner-trace.patch`, it is applied to `../faith-runner-trace`, and the reference clone stays clean. Commit regenerated traces together with TRACE_REFERENCE. (CLAUDE.md)
- Unreal: `D:\UE_5.8`. Tests run via `scripts/test-unreal.ps1`, the desktop suite via `scripts/test.ps1`, and both must stay green. The Runline module compiles with `/fp:precise` (enforced in `RunlineCoreBridge.h`).
- Merging to master is the user's decision.

## Review Focus

1. **Settings that are out of range or missing.** A hand-edited or empty config (sensitivity 0, a negative value, NaN, FOV 500) must load as clamped, sane values, and the game must still play. Test: Task 1 `Runline.Settings.ClampsAndDefaults`.
2. **Pausing mid-move.** Opening the menu during a wallrun or fall freezes the core: no steps run while paused, and the first frame after resuming doesn't step the time spent in the menu. Test: Task 2 `Runline.Menu.PauseFreezesTheCore`.
3. **Respawns and teleports with the effects running.** On a kill-plane death, the shake and the roll flip stop (camera.rs: Death clears trauma and flip), and the offsets don't sweep between the old and new places. Test: Task 5 `Runline.Movement.EffectsCutOnRespawn`.
4. **Look limits against unstepped look.** Drawing the mouse look before it is stepped must not show a pitch or yaw the look limiter is about to take back. The display may not push further past the current limit than the stepped view already is. Test: Task 5 `Runline.Movement.PendingLookRespectsLimits`.
5. **Camera motion turned to 0.** A player sensitive to motion sets "Camera motion" to 0: no bob, no roll, no shake, no somersault, while the FOV and swan neck still work. Test: Task 5 `Runline.Movement.CameraMotionZero`.

/// Every value is clamped on load and on set, so a hand-edited file can't break the game.

{
    GENERATED_BODY()
public:
    static URunlineSettings& Get();                 // the mutable CDO
    /// Multipliers on faith-runner's base sensitivity (mouse 0.0022 rad/count, pad 3.2 rad/s).
    UPROPERTY(Config) float MouseSensitivity = 1.0f;   // [0.1, 10]
    UPROPERTY(Config) float PadSensitivity = 1.0f;     // [0.1, 5]
    UPROPERTY(Config) bool bInvertMouseY = false;
    UPROPERTY(Config) bool bInvertPadY = false;
    /// Horizontal field of view, degrees (faith-runner's CameraFx fov_base).
    UPROPERTY(Config) float FieldOfView = 90.0f;       // [70, 120]
    /// Scales bob, sway, roll, shake and the roll somersault (0 = none; FOV and swan neck stay).
    UPROPERTY(Config) float CameraMotion = 1.0f;       // [0, 1]
    void Sanitize();                                   // clamps; NaN -> default
    void Save();                                       // Sanitize + SaveConfig

    /// invert and faith-runner's pad response).
    FVector2D MouseLook(FVector2D RawDelta) const;
    FVector2D PadLook(FVector2D Stick, float DeltaSeconds) const;
};
```

The pad helpers mirror faith-runner's `main.rs`:

- **Move:** below a 0.15 length the stick gives no move, and above it the raw value passes through. Move is summed across devices and clamped by the core.

This replaces the M2a dead-zone modifiers and closes the review minor about move accumulation: the Move action uses `EInputActionAccumulationBehavior::Cumulative`, so W+S cancels and keys plus pad add up, as in faith-runner.

/// Pitch range (down, up) and optional yaw half-range around the yaw the move started with, in radians.
struct LookLimit { float pitchMin, pitchMax; std::optional<float> yaw; };
/// The game's constraint for the current move (look.rs look_limit).
LookLimit LookLimitFor(const Controller& c);
/// Applies LookLimitFor to the controller's view: eases into a new limit over a moment, then holds it.
class LookLimiter { public: void Apply(Controller& c, float dt); private: std::optional<std::size_t> kind_; float entryYaw_ = 0.0f; float age_ = 0.0f; };
struct SwanNeckSettings { float startDeg, forwardCm, downCm; };
std::optional<SwanNeckSettings> SwanNeckSettingsFor(const Controller& c);
/// The camera's swan-neck offset; Update returns (forward, down) in metres, in the view's yaw frame.
class SwanNeck { public: std::pair<float, float> Update(const Controller& c, float dt); private: float forward_ = 0.0f, down_ = 0.0f; };
inline constexpr float MAX_LOOK_DOWN = -1.5707963f + 0.09f;   // -FRAC_PI_2 + 0.09
```

**Porting notes:**
- `uu(r)` is `r / 65536 * TAU` in f32. The limit table maps only the C++ `State` alternatives that exist. The states not ported yet (Barge, Stumble, Balance, ZipLine, Swing, Takedown, AirBarge, StepUp, RumpSlide, Vertigo, SwingJump, IntoClimb, ClimbExit, Climb) are listed in a comment saying they arrive in M4 with their states.
- `std::mem::discriminant` becomes `state.index()`.
- `wrap(a) = RemEuclid(a + PI, TAU) - PI`, using the core's `RemEuclid`.
- The order of operations in `ease` and in SwanNeck's `min(...)` stays exactly as in the Rust. `(dt / 0.07).min(1.0)` becomes `FMin(dt / 0.07f, 1.0f)`, and `((f - forward) * k).min(cap)` becomes `FMin((f - forward_) * k, cap)`.
- `to_degrees` is Rust's `self * (180.0f32 / PI)`. Write it as a local `Degrees(float r) { return r * (180.0f / kPi); }` and check that kPi equals Rust's `PI` (f32).

### Task 5: Effects in the movement component

**Files:**
- Modify: `Unreal/Runline/Source/Runline/Runner/RunlineMovementComponent.h/.cpp`, `RunlineRunner.cpp` (camera FOV)
- Test: `Unreal/Runline/Source/Runline/Tests/MovementComponentTests.cpp`

**Interfaces:**
- Consumes: `LookLimiter`, `SwanNeck`, `CameraFx`, `Shot` (Tasks 3-4), `URunlineSettings` (Task 1)
- Produces:

```cpp
// URunlineMovementComponent
float GetRenderFov() const;            // horizontal degrees (UCameraComponent::FieldOfView)
const runline::Shot& LastShot() const; // tests and the arms (step phase, gait)
```

**Per step**, in this order, matching faith-runner's app:
1. `Controller->Step`;
2. `Limiter.Apply(*Controller, StepSeconds)`;
3. `Fx.settings.fovBase = Settings.FieldOfView`;
4. `Shot = Fx.Update(StepSeconds, *Controller, In)`;
5. `Swan = SwanNeck.Update(*Controller, StepSeconds)`.

**Store the offsets, not the absolute values:**
- `EyeOffset = Shot.view.eye - Controller->GetView().eye`;
- `AngleOffset = (Shot.view.yaw - view.yaw, Shot.view.pitch - view.pitch, Shot.view.roll)`;
- the swan neck: `SwanNow = (fwd, down)`.

The previous step's offsets go into `Prev*`.

**Render:**
- eye = the interpolated core eye (M2a) + `Lerp(PrevEyeOffset, EyeOffset, Alpha) * Motion` + the swan neck, rotated into the render yaw: forward along `ForwardOf(yaw)` and down along −Y, in core coordinates before `ToUnrealPosition`;
- angles = the M2a interpolated yaw/pitch + `Lerp(prev, cur) * Motion`, where `Motion = Settings.CameraMotion` for bob, roll and shake.

The camera-motion scale applies to the offsets **except** the look-up assist and the landing pitch kick, because CameraFx folds them into pitch. Simplest correct rule: scale the whole angle and eye offset by `Motion`. Note in the ledger that at Motion 0 the assist and kick go too.

**Snaps:** on the core's Death, the adapter's `Respawn` and the NotPorted guard, set `Prev* = cur*` (Review Focus 3).

**Pending-look limit (Review Focus 4):** the displayed pitch is `clamp(interp + pending, FMin(lim.pitchMin, interp), FMax(lim.pitchMax, interp))`, with `lim = LookLimitFor(core)`. Do the same for yaw when `lim.yaw` is set, relative to the limiter's base: expose `LookLimiter::Base(const Controller&)`, returning slideYaw in a slide and entryYaw otherwise.
