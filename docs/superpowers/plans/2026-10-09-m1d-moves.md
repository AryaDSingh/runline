# M1d Core Moves Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn M1c's stubs for the Mirror's Edge signature moves into real ports, each proven by replaying faith-runner's own recorded tests bit-exact. The moves are wallrun, wallclimb (and its 180 turn and kick), ledge hang, shimmy and pull-up, slide, roll, vault, mantle and step-up, and springboard. This finishes the spec's M1 move list.

**Architecture:**
- **Same method as M1c.** Port function by function from `controller.rs` and `vault.rs` in source order. A move is "done" when the faith-runner traces that use it replay with zero divergence.
- **One harness for every trace.** Task 0 replaces the per-trace test cases with a single test that replays every committed trace and lists each one that diverges, with its first divergent frame and field. Adding coverage then means adding a name to `tools/trace/selected.txt`.
- **Candidate traces.** The traces each task adds were chosen by scanning all 183 recorded traces: those whose states stay within the moves ported so far, with default tuning, no fixtures, and a starting state the harness can rebuild. 59 already stay within M1c's core states. Each task's list is below.

**Tech Stack:** C++20 / MSVC `/fp:strict`, doctest, the trace pipeline (`tools/trace/make-traces.sh`), faith-runner `9470d755`.

**Spec:** `docs/superpowers/specs/2026-10-09-faith-movement-port-design.md` (M1's move list).

## Global Constraints

All of M1a–M1c's constraints apply:
- bit-exact comparison;
- `FMin`/`FMax`/`FClamp` only;
- every literal carries `f`;
- glam helpers ported from glam's source;
- Rust `f32::signum(0)` is `1`;
- ASCII sources;
- commit attribution.

Plus:
- **A trace is removed from the selection only with a ledger `Ruling:`** saying why, for example that it reaches a state a later milestone ports (melee, fixtures, takedown). Never to make the suite pass.
- **Stubs are converted, not widened.** If a trace reaches a stub this plan doesn't port, record it and leave the trace out. Never make the stub answer differently.

## Review Focus

1. **Wallrun entry geometry:** FindWallSide versus FindWallForward, the 57 degree limit and the 1.9 m wall height. Pinned by the 14 wall traces, which include a mesh wall turned off the grid.
2. **Slide braking and exit:** speed halved on exit; no stand-up in the first 0.5 s; jump does nothing mid-slide. Pinned by the slide traces (`jump_does_nothing_mid_slide`, `slide_lasts_half_a_second_and_halves_speed_on_exit`, `slide_steers_toward_the_view_and_brakes_out`).
3. **Roll timing:** a crouch pressed in the last 0.2 s before landing, with a 0.6 s retrigger lock. Pinned by `roll_needs_a_late_crouch_press` and `hard_landing_vs_roll`.
4. **Vault type selection** by height, depth, speed and rising. Pinned by the 17 vault traces, including the 6 `VAULT_TYPES` cases.
5. **Ledge hang on sloped or rough geometry** never leaves the body inside a rock. Pinned by `rough_shapes_tests__never_ends_up_inside_a_rock` and `pulls_up_onto_a_sloped_roof`.
